# BankLens

[![Live Demo](https://img.shields.io/badge/Live%20Demo-https%3A%2F%2Fbanklens.sysuin.com-blue?style=for-the-badge&logo=amazonaws)](https://banklens.sysuin.com)

**Live Web Application:** [https://banklens.sysuin.com](https://banklens.sysuin.com)

AI-powered bank statement analysis and banking product recommendation engine.
Upload a CSV bank statement and get an instant financial health report, a
customer profile generated by GPT-4o, and a personalised banking product
recommendation — all grounded in a RAG pipeline backed by ChromaDB.

---

## What it does

1. **Upload** a bank statement CSV (date, description, amount, type)
2. **Categorize** — transactions are auto-labelled using NLP keyword matching
3. **Analyze** — income, expenses, savings rate, and top spending categories are computed
4. **Retrieve** — ChromaDB finds the most relevant banking products from the knowledge base
5. **Profile** — GPT-4o generates a customer profile and recommendation grounded in the RAG context
6. **Display** — results shown across three interactive tabs in the Streamlit UI

---

## Architecture

```
CSV Upload
    │
    ▼
[categorizer.py]   NLP keyword matching → assigns category to each transaction
    │
    ▼
[analyzer.py]      Computes: income, expenses, savings rate, expense ratio, top categories
    │
    ▼
[rag.py]           Embeds financial summary → ChromaDB similarity search → top 3 product chunks
    │
    ▼
[agent.py]         LangChain chain: prompt + metrics + RAG context → GPT-4o → Pydantic model
    │
    ▼
[main.py]          Streamlit: Tab 1 (Transactions), Tab 2 (Metrics), Tab 3 (AI Profile)
```

## How RAG works in this project

The `knowledge_base/` directory contains six markdown files — one for each
banking product (Fixed Deposit, Personal Loan, Credit Card, Savings Account,
Recurring Deposit, Sweep Account).

At startup, BankLens:
1. Loads all six files and splits them into overlapping chunks using
   `RecursiveCharacterTextSplitter` (chunk_size=500, overlap=50)
2. Embeds each chunk using OpenAI `text-embedding-3-small`
3. Stores the embeddings in a local ChromaDB collection

When a customer statement is uploaded:
1. The computed financial metrics are converted into a natural language query
   (e.g. "Customer with income ₹85,000, savings rate 28%, top spend: Food")
2. ChromaDB runs a cosine similarity search and returns the top 3 most
   relevant product chunks
3. The retrieved chunks (with their source filenames) are passed to GPT-4o
   as grounded context — the model is explicitly instructed not to recommend
   any product outside the retrieved context
4. The UI displays which knowledge base files were used, making the
   recommendation fully transparent and explainable

The ChromaDB index is persisted to `./chroma_db/` on disk. Subsequent app
restarts load from the persisted index — no re-embedding occurs.

## How the LangChain agent works

`agent.py` builds a LangChain chain:

```
ChatPromptTemplate  →  ChatOpenAI (gpt-4o, temp=0.2)  →  PydanticOutputParser
```

The prompt combines:
- A system message from `prompts/system_prompt.txt` (persona, grounding rules, tone)
- The customer's financial metrics (JSON from `FinancialMetrics`)
- The RAG-retrieved product context (text + source filenames)
- Pydantic format instructions (injected automatically by `PydanticOutputParser`)

The output is validated against the `CustomerProfile` Pydantic model before
being passed to the UI. If GPT-4o returns malformed JSON, LangChain raises a
descriptive error rather than silently producing incorrect output.

## Local Setup (without Docker)

**Prerequisites:** Python 3.11+, an OpenAI API key

```bash
# Clone the repository
git clone https://github.com/your-username/banklens.git
cd banklens

# Create a virtual environment
python3 -m venv .venv
source .venv/bin/activate  # Windows: .venv\Scripts\activate

# Install dependencies
pip install -r requirements.txt

# Install the project itself so the 'app' package is importable.
# This is a one-time step — re-run only if you add new sub-packages.
pip install -e .

# Copy the environment template and add your OpenAI API key
cp .env.example .env
# Edit .env and set OPENAI_API_KEY=sk-...

# Run the app
streamlit run app/main.py
```

Open [http://localhost:8501](http://localhost:8501) in your browser.
Upload `data/sample_statement.csv` to try the app immediately.

## Local Setup (with Docker)

docker-compose up --build

The ChromaDB index is persisted in `./chroma_db/` via a Docker volume.
The knowledge base is embedded only on the first run.

## Environment Variables

| Variable | Required | Default | Description |
|---|---|---|---|
| `OPENAI_API_KEY` | Yes | — | Your OpenAI API key |
| `OPENAI_MODEL` | No | `gpt-4o` | LLM model for profiling |
| `OPENAI_EMBEDDING_MODEL` | No | `text-embedding-3-small` | Embedding model |
| `CHROMA_PERSIST_DIR` | No | `./chroma_db` | ChromaDB storage directory |
| `CHROMA_COLLECTION_NAME` | No | `banking_products` | ChromaDB collection name |
| `CHUNK_SIZE` | No | `500` | RAG chunk size (characters) |
| `CHUNK_OVERLAP` | No | `50` | RAG chunk overlap (characters) |
| `RETRIEVAL_K` | No | `3` | Number of RAG chunks to retrieve |

## CSV Format

The uploaded bank statement must be a CSV with these exact column names:

| Column | Type | Description |
|---|---|---|
| `date` | string | Transaction date (any parseable format) |
| `description` | string | Merchant name or memo |
| `amount` | float | Always positive |
| `type` | string | `Credit` or `Debit` |

Download `data/sample_statement.csv` from the app sidebar to see an example.

## AWS Deployment Guide

### Prerequisites
- An AWS account
- An EC2 t2.micro instance running Amazon Linux 2023 with Docker installed
- An Amazon ECR repository named `banklens`
- An IAM user with `AmazonEC2ContainerRegistryFullAccess` and EC2 SSH access

### GitHub Secrets to Configure

Go to your repository → **Settings → Secrets and variables → Actions** and add:

| Secret Name | Value |
|---|---|
| `OPENAI_API_KEY` | Your OpenAI API key |
| `AWS_ACCESS_KEY_ID` | IAM user access key |
| `AWS_SECRET_ACCESS_KEY` | IAM user secret key |
| `AWS_REGION` | e.g. `ap-south-1` |
| `ECR_REPOSITORY` | Full ECR URI (e.g. `1234.dkr.ecr.ap-south-1.amazonaws.com/banklens`) |
| `EC2_HOST` | Public IP or DNS of your EC2 instance |
| `EC2_SSH_KEY` | Contents of your `.pem` private key file |

### Deploy

Once secrets are configured, push to the `main` branch:

```bash
git push origin main
```

The GitHub Actions pipeline runs automatically:
1. **Lint** — black + flake8 checks
2. **Test** — pytest with coverage
3. **Build** — Docker image built and pushed to ECR
4. **Deploy** — SSH into EC2, pull latest image, restart container

The app will be available at `http://<EC2-public-IP>:8501`.
